# Architecture Placeholder

L1 模型抽象层负责统一外部模型调用接口,屏蔽具体 provider 差异,为后续编排和修复逻辑提供稳定输入。

L2 对话层负责需求澄清、上下文管理与多轮交互,把自然语言请求收束成可消费的结构化信息。

L3 编排层负责把任务拆成有顺序的生成步骤,协调模型调用、规则执行和中间产物流转。

L4 稳定性内核负责契约、校验、修复和漂移抑制,确保不同模型能力下仍能产出一致结构。

L5 生成管线负责把蓝图转换成代码、资源和运行时配置,并为前端与后端产物提供统一出口。

L6 交付层负责打包、部署、环境接线和沙箱适配,把生成结果变成可运行、可验证的最终交付物。
